# A3 — Did winning boards actually pay $1?

## Verdict

**Yes. 290 of 290 resolved boards paid exactly $1 to exactly one bucket. Zero exhaustiveness
anomalies. Buy-the-board's payoff assumption survives contact with reality.**

The only anomaly found is a **timing** anomaly, not a structural one: two boards are stuck
un-resolved 53h after their event date (details below). That is a capital-lockup risk, not a
strategy-killer.

## Method

1. Snapshot-copied `logs/negrisk_arb.jsonl` (54.9 MB, 336,739 rows) at 2026-08-02T04:33Z.
   Rows: 271,630 `sweep`, 35,568 `board`, 29,541 `shadow`.
2. Extracted every distinct event slug carrying a `board` or `shadow` row (i.e. every board the
   scanner actually **hit**, not merely quoted): **368 slugs**, of which **347** were seen on or
   after 2026-07-27.
3. Queried Gamma per slug: `GET https://gamma-api.polymarket.com/events?slug=<slug>` — 368/368
   returned HTTP 200 with a non-empty event, 0 errors, 0 missing. (0.4 s between calls.)
4. Per board, parsed every market's `outcomePrices`, `outcomes` (to locate the YES index the same
   way the scanner does), `closed`, `umaResolutionStatus`, `clobTokenIds`, `closedTime`,
   `negRiskOther`, plus the event's `negRiskAugmented`.
5. Cross-checked the **current** YES-token set against the token set the scanner cached at scan
   time (`logs/negrisk_tokens_v2.json`) — this is the test for a bucket being *added or removed
   after* we would have traded, which is the way exhaustiveness can break without any single
   market misbehaving.

Population split (event date parsed from the slug; "past" = event date ≤ 2026-08-01):

| | boards |
|---|---|
| hit by the scanner in the 07-27 → 08-02 window | 347 |
| event date already passed | **313** |
| event date is today/tomorrow (08-02, 08-03) — cannot resolve yet, excluded | 34 |
| of the 313: closed and resolved by Gamma | **290** |
| of the 313: event over but resolution still in flight | 23 |

## Results — the 290 resolved boards

| check | result |
|---|---|
| boards with **exactly one** bucket at `outcomePrices` YES = `1` | **290 / 290** |
| boards where every other bucket is exactly `0` | **290 / 290** |
| per-board payout sum (must be exactly 1.0) | **1.0 on all 290** — no other value occurred |
| boards with 11 legs | **290 / 290** (no board resolved with a different leg count) |
| markets voided / refunded / split-payout (any price ∉ {0, 1}) | **0** |
| markets left unresolved inside an otherwise-closed board | **0** |
| markets not `closed` inside a closed board | **0** |
| `umaResolutionStatus != "resolved"` | **0** |
| **buckets added or removed after our scan** (token-set drift) | **0 / 313** boards |
| boards carrying a `negRiskOther` catch-all bucket | **0** |
| boards with `negRiskAugmented = true` | **0** |

Both of those last two are genuine negatives, not missing-field artifacts: `negRiskAugmented` is
present on **368/368** event objects and explicitly `false` on all of them; `negRiskOther` is
present on **4,048/4,048** market objects and explicitly `false` on all of them.

The drift check is the important one and it is clean: for all 313 past-dated boards the set of
11 YES token ids Gamma returns today is **byte-identical** to the set the scanner cached when it
priced the board. The 11 legs we would have bought are the 11 legs that resolved.

The `negRiskOther` / `negRiskAugmented` result closes the other structural hole. Polymarket
*does* support "augmented negative risk", where placeholder outcomes and an explicit **Other**
bucket can be introduced after trading begins
(<https://docs.polymarket.com/concepts/negative-risk.md>). If a weather board ever shipped with
one, "buy all visible buckets" would stop being exhaustive. **No weather board in this sample has
either flag set.** This should be re-checked, not assumed, before go-live — it is a one-field
gate (`event.negRiskAugmented` / `market.negRiskOther`) and belongs in `board_sanity()`.

## Anomalies

**No exhaustiveness anomaly of any kind was found.** Every anomaly below is about *when* money
comes back, not *whether* it does.

### A3-1 (real, open) — two boards stuck un-resolved 53h after their event

| board | event endDate | state at 2026-08-02T04:51Z |
|---|---|---|
| `highest-temperature-in-hong-kong-on-july-31-2026` | 2026-07-31T12:00Z | `closed=false`, `acceptingOrders=true`, `umaResolutionStatus=null`, `umaResolutionStatuses=[]`, `umaEndDate=null` |
| `lowest-temperature-in-hong-kong-on-july-31-2026` | 2026-07-31T12:00Z | same |

Both are priced at 0.9995 / 0.0005 — the market knows the answer (27 °C high, 23 °C low) — but
**no UMA proposal has even been submitted**, so the 2-hour challenge clock has not started. The
same city resolved normally the day before
(`highest-temperature-in-hong-kong-on-july-30-2026` closed 2026-07-31T02:49:41Z, ~15h after its
endDate), so this is a stall on these two events specifically, not a Hong Kong-wide rule.

Impact: capital in these boards is locked with no bound. It does not change the payout, but it
breaks the "hold to resolution ≈ 1 day" assumption behind the $2.81/day-per-$100 column. A
go-live design must not assume a hard resolution deadline — the docs are explicit that there is
none in the other direction either ("There is no redemption deadline").

### A3-2 (informational) — 21 further boards from 08-01 are mid-resolution

Normal UMA flight, ~5–30h after event end. Nine of them already show 10 buckets at 0/1 with a
single bucket at `umaResolutionStatus: "proposed"` — i.e. inside the 2-hour challenge window.
Nothing wrong; just excluded from the 290.

### A3-3 (context, belongs to A2 not A3) — complete-board coverage is rare

Of 25,141 `buy` board rows in the window, only **921 (3.7%)** had `complete=true` (all 11 legs
quoted at once), spread across only **6 distinct boards**. A3 proves that *if* you hold all 11
legs you get paid; it says nothing about how often all 11 legs are quotable at once. That is A2's
question and this number suggests the answer matters a great deal.

## Resolution timing (the capital-lockup input)

Measured over the 290 clean boards, using each board's latest market `closedTime`:

| interval | min | p25 | median | p75 | p95 | max |
|---|---|---|---|---|---|---|
| resolution − event `endDate` | 0.39h | 6.58h | **10.40h** | 17.04h | 21.64h | 23.70h |
| resolution − 00:00Z of the event day | 12.39h | 18.58h | **22.40h** | 29.04h | 33.64h | 35.70h |
| resolution − last scanner sighting | 1.25h | 8.29h | **10.75h** | 13.55h | 24.54h | **56.74h** |
| spread of `closedTime` within one board | 0.55min | 2.45min | 5.97min | 107min | 326min | 487min |

Read: **money comes back a median of ~10.4 hours after the event window closes, ~22 hours after
the event day begins**, with a p95 near 22h and a hard tail past 56h (and the two A3-1 boards
still counting). The event's own `closedTime` matches its last market's to the minute
(median 0.00 min difference), so the event-level flag is a safe trigger.

The within-board spread matters for a subtle reason: a board's 11 markets do **not** all close at
the same instant — p75 is 107 minutes apart. Losing buckets are typically finalised well before
the winner. Any redemption trigger must key off the *winning* market, not the first one to close.

## What A3 does and does not establish

Establishes: for boards this scanner actually hit, the partition is real, exhaustive, and pays
exactly $1 — 290 independent confirmations, no counterexample, no leg drift, no void, no
catch-all bucket.

Does not establish: (a) that all 11 legs are *obtainable* — A2; (b) that resolution is timely —
A3-1 shows it sometimes is not; (c) that augmented negRisk will never appear on a weather board —
it is currently absent, and should be gated on rather than assumed.

# B4 — true on-chain cost of a round trip

## Verdict

**$0.024/position is right — almost exactly right — for the self-custody case, and roughly $3.46/day
too expensive for the documented Polymarket path, where the user pays no gas at all.**

Blended across the replay's own 953-execution mix, self-paid batched gas comes to
**$0.0239/trade** at the gas price Polymarket's own relayer is currently paying. The assumption is
$0.024. That is a coincidence, but a load-bearing one: gas is not what decides this strategy.

**What does decide it is not gas at all: a full YES set has no merge path back to collateral.**
See "The merge assumption is the real problem" below — this bears directly on the
$2.81/day vs $14/day question the test plan hangs on B4, and the answer is not a price.

### The merge assumption is the real problem, and it is structural, not a price

The test plan hangs "$2.81/day vs ~$14/day on $100" on being able to merge a set back to USDC
within ~10 minutes. Reading the deployed adapter
(<https://github.com/Polymarket/neg-risk-ctf-adapter/blob/main/src/NegRiskAdapter.sol>):

```solidity
/// @notice Merges a complete set of conditional tokens for a single question to collateral
function mergePositions(bytes32 _conditionId, uint256 _amount) public {
    uint256[] memory positionIds = Helpers.positionIds(address(wcol), _conditionId);
    ctf.safeBatchTransferFrom(msg.sender, address(this), positionIds, Helpers.values(2, _amount), "");
    ...
```

`mergePositions` takes **one `conditionId`** and burns **YES + NO of that same condition**. In a
negRisk weather event each of the 11 buckets is its own condition. Buy-the-board leaves you
holding **11 YES tokens across 11 different conditions** — never a YES/NO pair — so
`mergePositions` cannot be called on that inventory at all, at any gas price.

`convertPositions` runs the other way: it burns **NO** positions and returns YES of the complement
plus collateral ("Convert a set of no positions to the complementary set of yes positions plus
collateral"). There is no inverse function in the adapter's interface —
`splitPosition`, `mergePositions`, `redeemPositions`, `convertPositions` is the complete list.

So for the **buy** side (585 of 953 replayed executions, $15.02/day of the $17.92) the only exits
are: hold to resolution (median 10.4h after event end, per A3), or sell the legs back into the
book and pay taker fee plus spread a second time. **The ~$14/day "merge-in-10-min" column has no
contract path behind it as things stand.** Whether the V2 Combos stack
(`PositionManager`, `AutoRedeemer`, "Collateral Return — Release pUSD from compatible Combo
positions before resolution") re-opens it is exactly B5's question, and this finding should be
handed to B5 rather than settled here.

For the **short** side (buying NO on m buckets) the position *is* redeemable leg-by-leg after
resolution — m−1 or m of the NO tokens pay $1 — which is what the batched-redemption row above
prices.

## (4) Is $0.024/position fair, high, or low?

`negrisk_arb_pnl.py --gas` subtracts a flat charge **once per execution**
(`"profit": d["profit"] - gas`, line 123), default `0.024`. Against the replay's actual mix —
953 executions, 585 buy / 368 short, 144 trades/day, and a mean short-set size of **7.35 legs**
(weighted over all 7,630 in-window `short` board rows; leg counts cluster at 8 and 10, so this is
a mix estimate rather than a per-execution join):

| scenario | buy exit | short exit (7 legs) | blended / trade | $/day |
|---|---|---|---|---|
| **Relayed** (documented default, Polymarket pays) | $0 | $0 | **$0.0000** | **$0.00** |
| Self-paid, batched, @250 gwei | $0.0080 | $0.0335 | $0.0178 | $2.57 |
| **Self-paid, batched, @335 gwei** (operator's actual price today) | $0.0107 | $0.0448 | **$0.0239** | **$3.44** |
| replay's assumption | — | — | $0.0240 | $3.46 |

**Answer: $0.024 is fair — accurate to within 0.4% for self-custody at today's gas, and
conservative by $3.46/day if we use Polymarket's relayer.**

Caveats that cut both ways and should be stated plainly:

- The self-paid figure assumes **batching** all redemptions of a short set into one transaction.
  Unbatched, 7 separate redeems cost ~7 × $0.0107 = $0.075, i.e. **3× the assumption**
  (~$10/day at 144 trades/day, which would be material against an $11.97/day grind). Batching is
  not optional if we self-custody.
- It assumes POL stays near $0.0723 and baseFee near 250 gwei. Both were stable over the sampled
  24h (baseFee range 239.6–251.2 gwei) but neither is guaranteed; the cost scales linearly in
  their product.
- Entry gas is genuinely $0 in every scenario (finding 1), so all of this is exit cost.

**Bottom line for the go/no-go: gas is not the binding constraint on this strategy at any of the
prices measured.** The number that mattered here turned out not to be a price at all — it is that
buy-the-board has no merge path, which caps the buy side at the hold-to-resolution economics
(~$2.81/day per $100) until B5 finds otherwise.
